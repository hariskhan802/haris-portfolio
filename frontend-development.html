Frontend development can mean very different things depending on the product. I can join at the design-to-code stage, build a new interface from scratch, or improve an existing frontend that has become difficult to maintain.

Web applications & SaaS

Frontend stack

Tools I use for product frontend

React and TypeScript are at the center of my frontend work. Next.js is useful when the product needs routing, server rendering, data integration or a full application structure. I choose styling and component approaches based on the existing product rather than forcing one stack everywhere.

How I work

From brief to frontend build

The exact process changes by project, but the goal stays the same: understand the product first, build in visible stages, and handle the details before delivery.

01

Understand

Review requirements, designs, users, existing code and what needs to be delivered.

02

Structure

Plan layout, components, application states and the frontend architecture needed for the feature.

03

Build

Implement responsive components, data states, interactions and API-connected product flows.

04

Refine

Review responsiveness, empty/loading/error states, polish and maintainability before handoff.
